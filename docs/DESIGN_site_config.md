# 매장 설정 파이프라인 설계: 지도에서 웨이포인트와 직선 경로까지

작성: 2026-10-14 · 상태: 2단계 구현 중(수작업 값 + 검증), 자동 생성은 2-b단계 예정
관련 파일: `config/common/{entities,waypoints,zones}.yaml`, `scripts/validate_site_config.py`,
`ros_ws/src/serving_robot_navigation/serving_robot_navigation/site_config.py`

## 1. 목적

실제 상품이 될 때는 **지도가 만들어지면 웨이포인트와 직선 경로를 사람이 일일이 찍지 않고 시스템이 만들어야** 해요.
이 문서는 누가 무엇을 만들고, 어디까지 자동화할 수 있고, 어디에 사람의 확인이 남는지를 정해요.
같은 형식의 설정 파일을 손으로 쓰든 자동으로 만들든 똑같이 쓰도록 해서, 2단계의 수작업 값이 나중의 자동 생성 결과와 그대로 바뀔 수 있게 해요.

## 2. 담당과 산출물 (프로젝트 문서 기준)

| 항목 | 담당 / 시점 | 근거 |
|---|---|---|
| 지도(`map.yaml` + 이미지) + 좌표 기준표 | 지도 제작 단계 | 자율주행 설계안 4.1, 완료 산출물 |
| 테이블/주방/대기 위치(`waypoints.yaml`) | 지도 확정 직후, 자율주행 파트 | 통합 가이드 Q3-7 (한 곳에서만 관리) |
| 구역 폴리곤, 대기 포즈(`zones.yaml`) | **Fleet 파트 소유** | 통합 가이드 Q3-7 |
| ID 목록(로봇/테이블/구역) | `entities.yaml` (공통 config) | 통합 가이드 Q3-7 (문자열 하드코딩 금지) |
| 직선 통로 그래프 | **자율주행 파트** (지도를 보고) | 문서에 없음. 직선+제자리 회전 제약에서 나온 이번 설계 |

직선 통로는 지도만으로 정해지지 않아요. 로봇 크기, 안전 폭 규칙(통로 폭 0.8 m 이상), 가구 배치에 따라 정해지므로 지도가 넘어온 뒤 자율주행 쪽에서 만들고, 지도나 가구가 바뀌면 다시 검토해요.

## 3. 파이프라인 (실제 상품 기준)

| 단계 | 하는 일 | 누가 |
|---|---|---|
| 1. 지도 제작 | 로봇이 매장을 돌아 지도 생성 | 자동 |
| 2. 통로 그래프 제안 | 지도에서 직선 통로 후보 생성 (4장) | **자동** |
| 3. 테이블 지정 | 지도 위에서 "여기가 1번 테이블" 표시 (설치 때 한 번) | 사람 |
| 4. 서빙 위치 계산 | 테이블에서 가장 가까운 통로 위의 정차 위치와 바라볼 방향 | **자동** |
| 5. 검증 | 검증 스크립트가 설정을 지도/가구와 대조 | 자동 |
| 6. 승인 | 결과를 지도 위에서 보고 승인 (`status: reviewed`) | 사람 |

사람이 하는 일은 "표시와 확인"뿐이고 좌표를 직접 찍거나 경로를 그리지는 않아요.

테이블의 의미(이게 테이블이다, 몇 번이다)는 흑백 지도에 없어서 사람이 한 번은 지정해야 해요.
자동 추정(벽과 이어지지 않은 고립 장애물, 지도 제작 때 카메라 탐지)은 가능하지만 테이블/의자/기둥/화분을 구분하기 어렵고 번호는 매장이 정하는 것이라, 보조 수단으로만 써요.

### 승인 단계를 남기는 이유
음료를 들고 사람 사이를 다니는 로봇이에요. 폭은 충분한데 문턱이나 카펫이 있거나, 의자가 자주 튀어나오는 통로처럼 지도에는 안 보이는 사정이 있고, 지도를 만든 순간의 가구 배치가 계속 유지되지도 않아요. 그래서 자동 생성 결과를 사람이 한 번 보고 승인해요. 이후에 막히는 상황은 로봇의 막힘 대응(15초 알람, 30초 후 우회)이 처리해요.

## 4. 통로 그래프 자동 생성 방법 (2-b단계 계획)

지도(흑백 이미지)만으로 풀 수 있어요.

1. 지도에서 빈 공간만 뽑아요 (알 수 없는 영역은 제외).
2. 각 지점에서 가장 가까운 벽까지의 거리를 계산하고, 통로 폭이 기준(0.8 m)보다 좁은 곳은 제외해요.
3. 남은 빈 공간의 중심선(뼈대)을 추출해요. 로봇 경로 계획의 로드맵에서 쓰는 방법이에요.
4. 뼈대의 곡선을 직선 구간으로 단순화해요. 사각형 매장이면 대부분 수평/수직선이 돼요.
5. 교차점과 끝점을 노드로, 직선 구간을 연결선으로 만들어 같은 형식의 `waypoints.yaml`로 저장해요.
6. 각 연결선이 벽이나 가구를 통과하지 않는지 검증하고, 노드마다 제자리 회전 공간을 확인해요.

한계:
- 비스듬하거나 둥근 매장은 직선 단순화 결과를 사람이 더 많이 손봐야 해요.
- 지도에 없는 의자/테이블 상판은 가구 배치 정보(`entities.yaml`)로 보완해요. 지도에는 의자가 빠져 있어요.
- 자동 결과는 항상 5단계 검증을 통과해야 하고, 6단계 승인 전에는 `status: provisional`이에요.

## 5. 설정 파일 형식

세 파일 모두 `schema_version`, `status`(provisional | reviewed), 단위는 SI(m, rad), 좌표 프레임은 `map`이에요.
`authoring: manual | generated`로 어떻게 만들어졌는지 남겨요.

| 파일 | 내용 |
|---|---|
| `entities.yaml` | 로봇 ID, 테이블(월드 모델 이름, 중심, 상판 크기, 의자), 고정물(카운터, 화분) |
| `waypoints.yaml` | `nodes`(정차/회전 가능한 곳), `edges`(직선 통로, 소속 구역), `poses`(이름 붙은 목적지: 노드, 도착 방향, 종류, 별칭, 바라보는 대상) |
| `zones.yaml` | 이름 붙은 구역(직사각형). 알람 메시지의 위치 이름에 사용 |

목적지 이름: `standby_01`(별칭 `wait_01`, `home`), `kitchen`(별칭 `desk`), `table_01`~`table_04`.
PDF의 "kitchen" 이름을 기준 이름으로 쓰고 팀이 부르는 "데스크"는 별칭으로 받아요.

코드는 `site_config.py`로만 읽어요(이름 → 좌표/방향, 위치 → 구역 이름, 직선 구간 최단 경로). 설정 내용이 바뀌면 `revision`(해시)이 바뀌므로 실험 로그에 지도 revision과 함께 남겨요.

## 6. 검증 규칙 (`scripts/validate_site_config.py`)

지도와 가구, 월드를 읽어서 확인해요. FAIL은 반드시 고치고, WARN은 확인해요. 종료 코드는 FAIL 개수예요.

| 검사 | 기준 |
|---|---|
| 참조 | 노드/연결선/목적지/구역/별칭이 서로 일치하고 중복이 없음 |
| 월드 | 테이블/고정물 모델이 월드에 있고 같은 위치 (오차 2 cm 이내). `world_model`이 없는 항목(생성기 결과)은 WARN으로 알리고 건너뜀 |
| 노드 | 지도의 빈 칸 위, 제자리 회전 공간. HardStop 사각형(몸체 + `hard_stop_distance_m` 0.10 m)의 모서리가 도는 반지름 0.469 m 기준: +0.02 m 미만 FAIL, +0.10 m 미만 WARN |
| 연결선 | 직선, 중심선에서 가장 가까운 장애물까지 0.40 m 이상(통로 폭 0.8 m), 0.50 m 미만이면 WARN |
| 목적지 | HardStop 사각형(몸체 + 0.10 m)이 장애물에 닿지 않음, 테이블/주방이 정면(±25°), 로봇 앞면과 대상 사이 0.15~0.90 m |
| 구역 | 모든 노드가 어떤 구역에 속함 |
| 그래프 | 모두 연결, 모든 목적지 도달 가능, 통로 하나가 막혔을 때 우회가 없는 목적지를 WARN으로 표시 |

장애물에는 지도의 벽/카운터/기둥에 더해 **테이블 상판과 의자**(지도에 없는 가구)를 포함해요.
지도가 바뀌면 이 스크립트를 먼저 돌려서 어떤 값이 어긋났는지 확인하고 설정 값만 고쳐요. 코드는 건드리지 않아요.

## 7. 데모 매장의 값과 근거

월드(`cafe.world.sdf`)의 실제 치수로 계산한 통로예요. 여유는 중심선에서 가장 가까운 장애물까지의 거리예요.

| 통로 | 중심선 | 여유(검증값) | 비고 |
|---|---|---|---|
| 서쪽 세로 `aisle_west` | x = -3.2 | 0.50~0.75 m | 북쪽 끝은 카운터 앞 |
| 중앙 세로 `aisle_center` | x = 0.0 | 0.55~0.68 m | 의자 기준 |
| 동쪽 세로 `aisle_east` | x = 3.0 | 0.43 m (WARN) | 화분 근처, 좁음 |
| 테이블 줄 사이 `aisle_middle` | y = -0.4 | 0.65 m | 상판 기준 |
| 남쪽 가로 `aisle_south` | y = -2.4 | 0.55 m | |
| 북쪽 가로 `aisle_north` | y = 1.55 | 0.43~0.50 m | 카운터 앞은 0.50 m |

- 대기 위치(`standby_01`)는 남서쪽 모서리 `(-3.2, -2.4)`, 동쪽(+x)을 향해요. 직선 전용 설계라서 시작 위치가 통로 중심선 위에 오도록 이전의 `(-3.2, -2.25)`에서 옮겼어요.
- `kitchen`은 카운터 앞 `(-2.3, 1.55)`, 북쪽(카운터)을 향해요. 로봇 앞면과 카운터 사이 0.24 m.
- 테이블 `table_01`/`table_03`은 같은 노드 `T13`(x=-1.6), `table_02`/`table_04`는 `T24`(x=1.55)에서 서로 반대 방향(북/남)을 보고 서빙해요. 로봇 앞면과 상판 사이 0.39 m.
- 그래프는 테이블 줄 사이 통로, 서/중앙/동쪽 세로 통로, 남/북쪽 가로 통로가 이어진 격자 모양이라 한 통로가 막혀도 우회가 있어요.
- 값은 임시(`provisional`)예요. 매핑 팀원의 실제 지도가 오면 같은 방식으로 다시 만들고 검증해요.

## 8. 단계 계획

- **2단계 (진행 중)**: 형식 + 데모 지도용 수작업 값 + `site_config.py`(목적지 변환) + `go_to.py`(이름으로 이동) + 검증 스크립트. 3~6단계가 이 값으로 진행돼요.
- **2-b단계 (예정)**: 위 4장의 자동 생성 시제품. 같은 형식으로 출력해 수작업 값과 비교해요. PC에서만 돌릴 수 있어서 VM이 필요 없어요.
- **6단계**: 이 그래프를 따라 직선 구간 + 제자리 회전으로 주행하는 실행기, 막힘 대응.

## 9. 팀과 맞춰야 할 것

- `zones.yaml`은 문서상 Fleet 소유라서 현재 파일은 알람용 최소 임시본이에요. Fleet 담당자의 정식 구역 정의가 나오면 교체하고 `edges[].zone`의 ID를 맞춰요.
- 실제 지도를 저장할 때 `map.yaml`의 `free_thresh`는 0.196(또는 205가 빈칸이 되지 않는 값)이어야 해요. Nav2 저장 도구 기본값 0.25로 저장하면 알 수 없음(205)이 빈칸으로 읽혀요. 지도를 바꾸면 `python3 tests/robot/test_scan_filter.py` 로 확인해요.
- 목적지 ID(`kitchen`, `standby_01`, `table_01`~`04`)와 별칭이 Fleet/백엔드의 ID와 같은지 확인이 필요해요.
- "직선 통로 그래프로 경로를 정한다"는 방식이 계약 항목 17("사용자 정의 전역 플래너는 우선순위가 아님")과 충돌하지 않는지 설명이 필요해요. 이 그래프는 전역 플래너를 대체하지 않고, 우리 로봇이 직선으로만 다니는 제약을 위한 얇은 경로 선택 계층이에요.
